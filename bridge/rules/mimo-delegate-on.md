## 默认流程（每接到一个非平凡项目/任务就先做这件事）

1. **先加载 skill `mimo-delegate`**（`~/.dsh/skills/mimo-delegate/SKILL.md`）——
   这是默认入口，**不要等用户点名**。
2. 按它的分工表决定：哪些体力活派给 MiMo、哪些自己留。
3. 第一条回复里用**一句话**说明分工（谁做什么），让用户能确认技能确实被加载了。
4. 交付前做**独立验收**（磁盘 / API / 截图），不采信 MiMo 的自述。

（只有一步的琐碎请求——问一句话、改一行——直接做，不必加载。）

## 委托 MiMo Desktop（用户明确授权，长期有效）

本机装有**免费**的小米 MiMo Desktop。DSH 通过本地桥把"脏活累活"外包给它，
以降低 DSH 侧的花费。**用户的唯一标准：最终产品达标 + 少花钱。**

桥：`D:\Deepseek Harness\_mimo_bridge\MimoDesktop.ps1`
用法、接口表、全部实测结论与踩坑见同目录 `README.md`。

### 授权与边界

- **允许自启动。** `MimoDesktop.ps1 start` 会在应用未运行时拉起它；其它动作也会自动拉起。
- **绝不启动第二个实例。** 重复实例会用新端口改写 `desktop-api.json`，直接打断正在工作的桥。
- 桥是非官方内部接口，随应用更新可能失效；失效就退回到自己动手，不要死磕。

### 分工

- **默认派给 MiMo（含"读与想"）**：翻代码库 / 查文档 / 读日志 / 搜字符串 / 总结大文件；
  定位 bug、比较方案、摸清某个 API 的真实用法；批量脚手架、素材生成（图片）、
  文档/PPT、重复性改动、长跑任务。
- **我负责**：拆任务、写清验收标准、**独立验收**（只做定向小证据：读关键行 / 跑一条命令 /
  看一张截图），**永不采信它的自述**；再加集成、收尾与最终交付。
- **经济账**：DSH 侧每一次"读 + 想"都要花钱，MiMo 免费——所以**读与想默认外派**，
  我只读它的结论并抽验 1-2 条关键断言，**不把它读过的原文整块拉进我的上下文**。
  反模式：自己去翻第三方打包代码、抠 CLI 解析器半小时（上一轮真犯过）。
- **外派规格必须窄**（实测：1 文件 1 问题 = 10 秒；8 文件交叉审计 = 3 分 48 秒）：
  一次 ≤3 个文件；写明**范围白名单**（不要读其它文件 / 不要搜目录 / 不要跑无关命令）；
  写明**工具调用上限**（读文件类 ≤12）；固定输出格式（≤5 条、每条一行）；禁止解释背景与写总结。
  大审计拆成几个窄任务，不要一份规格塞 8 个文件。
- **模型按活选**：机械读 / 核对 / 计数 → `-Model mimo-flash`；复杂生成 → `mimo-auto`；
  难判断 → `mimo-pro`。
- **等待有预算**：`send` 会返回 `mark`，用 `wait -Since <mark> -TimeoutSec 240` 只等自己那一轮；
  **超时就自己做，不干等**。限定 mark 还能避开"用户在同会话手打的轮次"污染测量
  （今晚误判过一次：真实 3 分 48 秒被读成 570 秒）。
- **绝不把"自测 / 反复验证"派出去。**（2026-09-18 真踩过：一份"加重试并自测"的规格让它先假死 3 分钟，
  恢复后进入**并行暴走**——同一批自测重复了几百次工具调用、开出大量并行 PowerShell 进程、
  在共享目录反复建删 `tmp-*`、重复提交，最后把机器拖崩。）规矩：规格里只写**要改成什么样**，
  并明确写上"**不要自测 / 不要循环验证 / 不要并行跑**"；验证由我在侧边做定向小证据。
- **发现暴走立刻接管，不等它自己收敛。** 信号：`progress` 里同一动作反复出现、`newTools` 短时间内爆量、
  共享目录冒出 `tmp-*` 残留、同名提交重复出现。能 steer 就 `send` 一句"立刻停止，只回 N 行"；
  若返回 `409 busy`（它在自锁里），**等一轮就接管**，不要反复 probe 它。
- **`wait` 返回 `stalled` 不等于死了。** 它只是"150 秒没有新事件"（实测会自己恢复，且恢复后可能开始暴走）。
  处置顺序：先看磁盘上活干完没有 → 干完了就**接管收尾**；没干完就换**更窄**的规格再派一次；
  **禁止原样重派**，同一规格最多派两次。
- **一个任务一个会话。** 派活前用 `newproject -Dir <项目文件夹>` 把 MiMo 的项目指向与 DSH 相同的目录，
  再用 `newtask -Dir <项目文件夹> -Message <任务>` 在**该项目下新建会话**并提交；返回的 `sessionId` 用于后续
  `send` / `wait`。这样同一项目的多个任务互不污染上下文，用户也能在 MiMo 侧栏按项目看到它们。
  这两个动作是 UI 自动化（见 `README.md`「新建项目 / 新建会话」）：执行时会短暂接管键盘焦点，
  `MimoUiAuto.ps1` 必须在火绒信任区里，且**不要**在用户正在打字时调用。
- **接管条件**：连续 2 次产出不达预期，或卡在同一个限制上 → 亲自做完，不再重复派同类活。
- **实时进度**：长任务派出去后，让用户双击 `_mimo_bridge\MimoProgress.cmd` 在自己的窗口里
  实时看 MiMo 的思考 / 工具调用 / 文件产出（`-Follow` 可一直等下一轮）。我自己用 `progress`
  动作按段取增量、只汇报要点——**DSH 侧的我只能在回合结束时说话，无法主动播报**，
  所以实时窗口必须由那条控制台提供。
- **成本纪律**：不为了省事把活全留给自己，也不为了外包而反复返工。
  长任务用 `send` + `wait` **分段**等待，每段都向用户反馈，禁止长时间静默。
- 派活时必须 `-Dir` 钉住工作目录：MiMo 的 bash 默认落在 `C:\Users\MI\XiaomiMiMoProjects`，
  不是会话目录；并带 `-Origin <会话的 convo id>`，用户才能在界面里看到这条请求。
- **桥一改就同步 skill，并且要验证。** 任何对 `MimoDesktop.ps1` 的改动（新动作 / 新参数 /
  行为变化）之后：抬高 `$BridgeVersion` → 同步 skill 的 `bridge-version:` 戳与动作表 →
  跑 `_mimo_bridge\Check-Drift.ps1`，必须 `IN SYNC` 才算改完。

## MiMo 委托的 UI 开关（插件仓库）

- 仓库：`https://github.com/Qamar-crypto/DSH-skill`（public）——侧栏按钮
  （压在「上下文洞察」上面）+「设置 → 插件 → 插件配置」卡片，用来开/关这条流水线。
- 本地源码：`_mimo_bridge\plugin\dsh-plugin-mimo-delegate\`（含两个自证脚本
  `preflight.mjs` / `client-preflight.mjs`）。
- **改它之前必读**：宿主半的 `apply()` 一旦抛异常，会让整个 DSH 启动失败并掉进恢复界面
  （2026-09-17 真出过一次：假设了 `ctx.settings.watch` 存在）。规矩：不假设任何 API、
  全部能力探测、`apply` 内一律 try/catch，改完必须跑两个 preflight 直到都 PASS。
